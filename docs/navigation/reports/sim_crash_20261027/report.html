Gazebo Livox 충돌 진단

Gazebo 종료 · 2026-10-27 15:04:58

커널 로그는 gzserver가 libros2_livox.so에서 segmentation fault로 종료됐음을 보여줍니다. launch는 필수 프로세스 종료를 감지하여 gzclient도 종료했습니다. 현재 재실행한 Gazebo는 유지했습니다.

충돌 위치와 재현

ELF 주소 0x40cf0은 LivoxPointsPlugin::InitializeRays의 scan pattern direction 읽기입니다. 누적 currStartIndex는 int64_t인데 반복 변수 k는 int입니다. 실제 설정 samples=40000, pattern size=800000에서 53,688번째 scan은 32비트 범위를 넘으며 k=-2147483648, index=-283648이 되어 aviaInfos 범위 밖을 읽습니다. 월드 시각을 Reset해도 플러그인 누적 값이 반드시 초기화되지는 않습니다.

Out-of-bounds pattern access: k=-2147483648, index=-283648, size=800000

최소 재현 코드에서 실제 배열 접근 전에 이 잘못된 index를 검출했습니다. 충돌 명령 주소도 해당 읽기와 일치하지만 이번 전체 core/register dump는 확보되지 않았으므로 유일한 원인을 core로 확증한 것은 아닙니다. 새 controller_odom 노드가 Gazebo를 직접 종료했다는 기록은 없습니다.

수정과 검증

스캔 패턴 순서를 보존하면서 시작 index를 매 scan 패턴 길이 안으로 순환시키고, scan 내부 offset은 64비트로 처리했습니다. 빈 패턴/0 이하 samples도 초기화 단계에서 거절합니다. 기존 timestamp·snapshot·거리 로직은 유지했습니다.

  • 원래 32비트 경계에서 음수 index 재현.
  • 동일 패턴, wrap, downsample, INT32 범위를 두 번 넘는 누적 길이 검증 통과.
  • UBSan을 적용한 새 sequence 검사 통과.
  • CTest 4개 통과: index regression, 중복 점군 검사, 격리 Gazebo 정적/이동 센서 검사.
