방향별 거리 필터 비교

전방 0.3m / 측후방 1.0~1.5m
별도 실험 패키지

2026-10-27 · src/legged_range_trial

근거리 자가 반사 비교를 위한 설정이다. 이전 바닥·단차 오검출과 전역 플래너의 출발점 거절을 해결한 버전은 아니다. 기존 navigation/global planner 소스와 기본 설정은 수정하지 않았다.

설정

항목기본 range.yaml비교 range15.yaml
전방 ±60°0.3m0.3m
그 밖의 방향1.0m1.5m
costmap obstacle_min_range0.3m0.3m
몸체 높이 조건기존 −0.35~1.5m 유지

센서 원점의 3D 거리다. 전방 방향은 고정 장착 TF로 로봇 +X에 맞춘다. 측후방 실제 장애물도 함께 제외되므로 1.0m부터 비교한다. costmap 최소 거리가 0.3m여도 앞 단계에서 버린 측후방 점을 복구하지는 못한다. clearing 최소 거리는 기존 0.0m를 유지한다.

과거 기록 비교

기존 필터 출력 267 scan, 1,515,119점에 새 거리 조건을 적용했다. 1.0m에서 12.30%, 1.5m에서 29.59%를 추가 제외했다. 문제를 일으킨 의심점 424개는 모두 1.88~3.99m 거리에 있어 두 설정 모두 통과한다. 점 수 감소를 CPU 감소율로 해석할 수는 없다.

연산량

기존 C++ 필터를 재사용하며 단계 수와 알고리즘은 그대로다. 제곱 거리와 cos² 비교로 처리하고 점마다 atan2/sqrt를 호출하지 않는다. CUDA/CuPy나 관절 TF를 추가하지 않는다.

중력 기준 높이 계산도 중력 방향 벡터가 준비되면 점당 3회 곱셈·2회 덧셈으로 기존 높이 내적을 대체할 수 있다. 따라서 Orin NX에서 감당하지 못한다고 미리 단정할 작업은 아니다. 다만 시각에 맞는 자세 취득과 통신을 포함한 Jetson 실측은 아직 없다.

검증

패키지 빌드, 두 프로필의 센서 장착 회전·각도 경계·메시지 보존 검사 통과. 기본 프로필로 격리 도메인에서 DWB 경로/명령 생성·장애물 우회·근접 정지·센서 중단 정지 확인. 원본 175개 파일의 변경 없음 확인. 사용자 시뮬레이터와 navigation을 실행/변경하지 않았다.

실행

기존 navigation을 종료하고 Gazebo·localization을 유지한 상태에서:

source /home/kim/legged_robot_ws/install/local_setup.bash
ros2 launch legged_range_trial navigate.launch.py \
  site:=/home/kim/legged_robot_ws/maps/sim_site_v1/site.yaml \
  use_sim_time:=true \
  cloud_topic:=/livox/lidar_PointCloud2

기본 controller는 DWB, odometry는 /Odometry, RViz는 켜진다. 1.5m 비교는 위 명령에 다음을 추가한다.

filter:=/home/kim/legged_robot_ws/src/legged_range_trial/config/range15.yaml

필터만 확인하려면:

ros2 launch legged_range_trial preview.launch.py use_sim_time:=true

RViz 출력 토픽: /range_trial/obstacles. 이 preview는 속도 명령을 발행하거나 기존 navigation 입력을 바꾸지 않는다.
