## 채움 방법

1. 기존 2D 지도의 실제 free/occupied/unknown 기준과 좌표를 사용했다. 장애물과 unknown에서 최소 35cm를 남겼다.
2. 과거 PCD 바닥과 이번 바닥의 지역 높이 차이를 보정한 참조값을 사용했다. 기존 reference audit의 결과를 재사용하며 좌표나 원본을 이동하지 않았다.
3. 관측 영역 내부/닫힘 영역의 빈 셀 중 현재 바닥에서 1.25m 이내, 기존 PCD 바닥 근거에서 0.30m 이내만 후보로 삼았다.
4. 최대 2m 주변의 바닥으로 강건 평면을 적합하고, 양쪽 지지가 없는 외삽은 제외했다. RMS 18mm 이하, 기울기 0.04 이하, 보정 PCD와 높이 차이 35mm 이하만 수용했다.
5. 알려진 단차 보호 영역과 다른 높은 물체 주변 20cm는 제외했다. 기존 높은 셀은 확인된 작은 사람 흔적 ROI 외에는 바꾸지 않았다.

`provenance.npz`에 원래 관측, 추가 추정 바닥, 수정된 사람 흔적, 보호 단차, 원본/결과 높이와 평면 RMS를 별도로 저장했다.
**RGHM v1 자체는 관측/추정의 구분을 표현하지 못하므로 Nav2에서는 추가 셀도 일반 usable 높이로 들어간다.** 이 후보를 관측 원본으로 취급하지 말고 provenance 파일을 함께 보관해야 한다.
추정 셀의 variance=0.0009와 원본 snapshot timestamp는 호환성 인코딩이다. 새로운 센서 관측이나 검증된 확률 오차를 의미하지 않는다.

## 실제 Nav2 비교

모든 검증은 별도의 localhost ROS domain 187에서 planner만 실행했다. FollowPath/controller/LCM은 실행하지 않았고 명령 토픽이 없음을 확인했다.

| 복도 → 먼 목표, 기본 500ms 계산 예산 | timeout | timeout |

추가로 **검토 전용 5000ms 계산 예산**을 시험했다.
- (8.975,37.975) → (48.5973,41.4554): 성공 855 poses, 전체 요청 약 2.07초.
- (8.975,3.975) → 같은 목표: 성공 1536 poses, 전체 요청 약 3.12초.

따라서 긴 경로 timeout을 빈 바닥 오류로 혼동하면 안 된다. 위 시간은 전처리/통신을 포함한 전체 요청이며 1Hz 주행 중 재계획 성능을 만족한다는 뜻은 아니다. 실제 주행 기본 파라미터는 변경하지 않았다.

다섯 단차 핵심 영역의 관측 높이와 유효 마스크는 모두 동일하다. 수치는 metrics.json의 step_core_checks에 기록했다.
과거 PCD/점유 지도는 새로 놓인 물체의 부재를 증명하지 못한다. 근거 부족 영역은 계속 unknown으로 남는다.

## 다시 열기

```bash
cd ~/legged_robot_ws
source tools/navigation_env.sh
export ROS_DOMAIN_ID=186
export ROS_LOCALHOST_ONLY=1
ros2 launch legged_bringup rubi_height_navigation.launch.py \
  mode:=review use_sim_time:=false \
  site:="$PWD/maps/rubi_1f_height_20261109_floorfill/site.yaml" \
  review_planning_time_ms:=5000
```

기존 review launch는 먼저 그 터미널에서 Ctrl+C로 종료한다. ROS bag 없이 사용할 수 있다.
2D Pose Estimate는 검토 시작점을, 2D Goal Pose는 경로 목표를 지정한다. 실제 로봇 위치를 추정하거나 주행시키는 모드가 아니다.
먼 복도 경로 확인은 시작 **(8.975,37.975)**, 목표 **(48.5973,41.4554)**가 검증된 조합이다.
`review_planning_time_ms`는 review 모드만 적용되고 기본값은 기존 500ms다.
